# SGSPE · Fase 7, plan 7.1 (modelo): plan de implementación

> **Para agentes:** SUB-SKILL OBLIGATORIA: usar superpowers:subagent-driven-development (recomendada) o
> superpowers:executing-plans para ejecutar este plan tarea por tarea. Los pasos usan casillas (`- [ ]`) para el
> seguimiento. Cada tarea de código sigue superpowers:test-driven-development: prueba que falla, implementación mínima,
> prueba en verde, commit.

**Goal:** Dejar en `~/IdeaProjects/sgspe` el modelo de F7 («IA») aprovisionable de punta a punta —`ai_suggestion`
(`apiOnly`, WF-K) y `ai_interaction` (`apiOnly` y `appendOnly`) con el catálogo «Tipo de sugerencia de IA», la llamada a la
IA de `commitment_candidate`, sus permisos y la cita restringida en `model/roles.json`, los dos objetos clasificados en
`ProjectScope`—, la tabla fija `sgspe.knowledge_chunk` con su migración `sgspe_ai` y su índice GIN de texto completo en
español, y la base de pruebas `F7ApiTest` que usan los planes 7.2a, 7.2b y 7.2c.

**Architecture:** El modelo sigue siendo datos en `model/` aplicados por REST con Python de solo biblioteca estándar
(ADR-0007): dos scripts de un solo uso (fuera del repositorio) insertan en `model.json` y `roles.json` lo de las fichas y la
matriz de `security.md` tal como las dejó el plan 7.0, y `test_model.py`, `test_apply.py` y `test_apply_roles.py` los
mantienen iguales a los documentos. `design_docs.py` aprende a leer la ficha de una tabla fija, y `test_model.py` compara
con ella la migración de `knowledge_chunk`. Del Kotlin, este plan toca solo lo que el modelo nuevo rompería o abriría sin
tocarlo (`ProjectScope.ROOTS`, `CandidateLinks.TENANT_CAPABLE`, `CommandTransitionGuard.COMMANDS`,
`AmountFieldsGuard.NOT_MONEY` y las pruebas que cuentan objetos), crea el primer archivo de `sgspe.ai`
(`KnowledgeMigration`, la `ModuleMigration` de la tabla fija) y deja `sgspe.F7ApiTest`.

**Tech Stack:** Kotlin 2.4.20, Spring Boot 4.1.1 (WebFlux con corrutinas), JDK 25, Gradle 9.8.0, `wasichai-bom` 1.2.0 (sin
starters nuevos: el de agente llega con 7.2a); R2DBC y Flyway por `ModuleMigration` de wasichai; Jackson 3
(`tools.jackson`); JUnit 5 con `wasichai-test`; PostgreSQL 18 con PostGIS 3.6 (texto completo `spanish`, sin extensiones
nuevas); Python 3.11 o superior (solo biblioteca estándar).

**Spec:** `docs/superpowers/specs/2026-10-12-fase-7-design.md` (vinculante): objetivo y restricciones globales, §2.2
(elecciones 1 y 9), §4 (entero: es este plan), §5 (filas «De integración» que tocan el modelo y «Arquitectura») y §7
(fila 7.1, «Paralelismo», «Tareas del coordinador de la fase»). Los documentos como los dejó el plan 7.0 (en `main` desde
sgspe #56): `docs/database-model.md` §2.3, §4 (fila `ai_suggestion_kind`), §20 (fichas de `ai_suggestion`,
`ai_interaction` y `knowledge_chunk`) y la ficha de `commitment_candidate`; `docs/domain-model.md` §4.7, §4.10, §6.5,
§6.18, §7.2 y §7.3; `docs/security.md` §7.1, §7.8, §7.9, §9.7 y §14 (fila `test_apply_roles.py`); `docs/workflows.md` WF-K
(«WF-K para sugerencias de IA») y «Transiciones de comando»; `docs/ai-architecture.md` §9 y §13.2;
`docs/requirements-analysis.md` §10 («Tipo de sugerencia de IA»). Lo que la especificación asigna a 7.2a (starter de
agente, activación, `Pseudonymizer`, `Interactions`, AI-05), a 7.2b (`POST /ai/runs`, `SuggestionWriter`, aceptación,
`AiSuggestionWorkflowApiTest` con el endpoint), a 7.2c (JOB-07, `KnowledgeSearch`, AI-06, AI-07) y a 7.3 (portal) queda

## Global Constraints

- **Repositorio y ramas.** Todo el trabajo en el worktree `~/IdeaProjects/sgspe-wt/f71`, en la rama `feat/fase-7-1-modelo`
  creada desde `main` con el plan 7.0 integrado. Cada tarea en su rama `f71/t<k>` creada desde `feat/fase-7-1-modelo` con
  las tareas de las que depende ya integradas, y se integra con `git merge --no-ff f71/t<k>`. Los planes 7.2a, 7.2b y 7.2c
  parten de esta rama ya integrada en `main`. En los comandos, `$REPO` es `~/IdeaProjects/sgspe-wt/f71`.
- **Versiones.** wasichai `1.2.0` exacto, Kotlin `2.4.20`, Spring Boot `4.1.1`, JDK `25`, Gradle `9.8.0`, ktlint `1.7.1`.
  Ningún starter nuevo en este plan.
- **Idioma.** Español (es-PE) en documentos, comentarios, mensajes y `detail`; nombres técnicos en inglés (ADR-0009);
  valores ENUM en español MAYÚSCULAS sin tildes (`BORRADOR DE ACTA`).
- **Arquitectura.** Nunca código bajo el paquete `wasichai`; nunca `RecordStore`, `PhysicalTableRecordStore`,
  `AuditService` ni `ObjectSchemaManager`; `scope` y `privacy` solo dependen de `common`; ningún paquete de dominio importa
  `sgspe.ai`; ningún literal de rol en `src/main/kotlin` (`ArchitectureTest`). Ningún import sin uso: ktlint de este
  repositorio no los quita.
- **La IA nunca escribe datos de dominio** (`ai-architecture.md` §16): nada de este plan acepta, aplica una transición de
  dominio ni llama a un modelo. `accept` de WF-K de `ai_suggestion` queda cerrado por la API genérica desde que existe
  (`CommandTransitionGuard`), aunque su endpoint llegue en 7.2b.
- **Tenants de F6.** Un tenant que todavía no tiene el modelo de F7 sigue con F6: nada de este plan lee los objetos nuevos en
  `src/main/kotlin` fuera de las tablas de las guardas, que solo se consultan cuando la escritura es de ese objeto.
- **Modelo.** Ningún campo con `editable`; un derivado lleva `"derived": true` (`run_by_platform`). Ninguna acción
  declarada, tipo de documento ni automatización nuevos. `model/` está fuera de prettier: los JSON van con el formato a mano
  de este plan.
- **Tabla fija.** `sgspe.knowledge_chunk` con las columnas de su ficha **sin** `embedding` (§2.2.9 de la especificación,
  CON-035), sin claves foráneas entre esquemas, con su migración propia `sgspe_ai` (`classpath:db/sgspe/ai`). Una migración
  aplicada nunca se edita (WAS-ADR-0026): un cambio posterior es `V2__…`.
- **Datos de prueba.** Ficticios: correos `@sgspe.test`, «Proyecto Ejemplo A», «Comunidad Ejemplo»; textos de la IA solo
  con marcadores (`[PERSONA]`, `[PERSONA:<id>]`); modelo `modelo-de-prueba`; ningún nombre real de persona (RQ-SEC-018).
- **Entorno.** Ningún subagente corre `integrationTest`, ni toca Docker, el túnel, bases de datos ni el tenant de
  desarrollo: esos pasos dicen «(coordinador)». Los subagentes compilan (`build`, que compila también las de integración),
  corren las pruebas de Python y las unitarias, y entregan la tarea marcada «integración pendiente» con sus clases.
- **Gradle.** Siempre `GITHUB_ACTOR=$(gh api user -q .login) GITHUB_TOKEN=$(gh auth token) ./gradlew …` desde `$REPO`;
  `./gradlew ktlintFormat` antes de `build`. El token nunca se imprime ni va a un archivo. Con poca memoria,
  `-Pkotlin.daemon.jvmargs=-Xmx3g`.
- **Aprovisionamiento.** Siempre `apply.py` → `apply_roles.py` → `apply.py --workflows` → `load_ubigeo.py` →
  `publish_layers.py` (omitible con `--skip-layers`). La tabla fija no es un paso: la crea Flyway al arrancar el backend.
  El tenant `demo` sube a F7 por la tarea del coordinador de la fase (§7 de la especificación), no en este plan.
- **Commits.** Conventional Commits con asunto en español; cuerpo de 100 columnas como máximo (contadas en caracteres); al
  final, tras una línea en blanco, `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>` y
  `Claude-Session: https://claude.ai/code/session_01RmiD2JE3gkHdBNUraZkjgM`. `git add` solo con rutas explícitas; nunca
  `initial-promp.md`, `arch-*.md`, `tech-landing.txt` ni nada de `~/Documents/gspe`. `yarn format` antes de commitear yaml
  o json fuera de `model/` (este plan no toca ninguno). El cuerpo del PR termina con
  `🤖 Generated with [Claude Code](https://claude.com/claude-code)` y la línea de la sesión.
- **Scripts de un solo uso.** `gen_model_f7.py` y `gen_roles_f7.py` se guardan en `$SCRATCH` (el scratchpad de la sesión
  de quien ejecuta, fuera del repositorio: `export SCRATCH=<scratchpad>/f7-1 && mkdir -p "$SCRATCH"`), se corren una vez

## Review Focus

Las cinco entradas que la especificación implica y que más pueden morder a quien use esto, cada una con su prueba en la
tarea dueña del código:

1. **Aceptar una sugerencia por la API genérica** (`POST /api/objects/ai_suggestion/records/{id}/transitions/accept`)
   entre 7.1 y 7.2b, o después por una vía que no es el endpoint. `apiOnly` no rechaza transiciones (WAS-ADR-0040): sin
   guarda, cualquiera de los seis roles de WF-K la llevaría a `accepted` sin ejecutar ningún comando. Se espera `403
   COMMAND_ONLY` y la sugerencia en `proposed`. Pruebas: `CrossGuardsTest` «aceptar una sugerencia de IA solo llega por su
   comando» (Tarea 2) y `AiSuggestionWorkflowApiTest` «aceptar por la API generica es 403 COMMAND_ONLY» (Tarea 5).
2. **Subir el tenant `demo` (que ya tiene datos) de F6 a F7.** Se espera que `apply.py` cree solo los dos objetos y las
   cuatro relaciones, sin un campo nuevo ni un `PUT` sobre un objeto anterior; que `apply_roles.py` actualice 13 roles y
   deje igual a `SOCIAL_INVESTMENT_MANAGER` y `GIS_ANALYST`; y que una segunda corrida no escriba. Pruebas:
   `test_a_tenant_of_f6_moves_to_f7_adding_only_the_two_objects_and_their_relationships`, `test_un_tenant_de_f6_suma_la_ia`
   (Tarea 2) y, contra wasichai de verdad, `TenantProvisioningApiTest` (Tarea 2, coordinador).
3. **La cita de la IA ante quien no descarga evidencias restringidas.** `evidence_quote` puede citar un acta
   CONFIDENCIAL; `AUDITOR` lee todo el tenant y, en el futuro, un rol nuevo podría leer `ai_suggestion` sin
   `DOWNLOAD_RESTRICTED`. Se espera que la API genérica no le devuelva la clave y que los lectores de la cita sean
   exactamente los roles con `DOWNLOAD_RESTRICTED` sobre `evidence`. Pruebas:
   `test_la_cita_de_la_ia_la_leen_exactamente_quienes_descargan_evidencias_restringidas` y `FieldPermissionsApiTest` «la
   cita de una sugerencia de IA solo la ven quienes descargan evidencias restringidas» (Tarea 2).
4. **Un candidato de IA con la interacción de otro proyecto, o del tenant.** Con `ai_interaction` en `ProjectScope.ROOTS`,
   `CandidateLinkRule` juzga el campo nuevo `commitment_candidate.ai_interaction` (sale del catálogo): una interacción de
   otro proyecto debe ser `409 PROJECT_MISMATCH`, pero una del tenant (sin `project`, como la de AI-05 o JOB-07) no es de
   otro proyecto. Pruebas: `CandidateRulesTest` «una interaccion de IA del tenant o del proyecto pasa y una de otro
   proyecto no» (Tarea 2) y `AiModelApiTest` «un candidato de IA no cita la interaccion de otro proyecto» (Tarea 4).
5. **Corregir una `ai_interaction`** (un portal, un script o el propio código de `sgspe.ai`). Se espera `403` por la API
   genérica, también al admin, y `409` dentro del proceso, también como la plataforma, sin cambio en el registro
   (RQ-AUD-003). Pruebas: `AiModelApiTest` «la API generica no escribe ninguna salida de la IA, ni al admin» y «una
   interaccion no cambia ni se borra, tampoco como la plataforma» (Tarea 4).

### Workflow (`model/workflows/ai_suggestion.json`)

- `wf-k-ai_suggestion`, «Sugerencia de IA»: `proposed` (Propuesto, inicial) → `accepted` (`accept`, Aceptar), `rejected`
  (`reject`, Rechazar), `duplicate` (`mark_duplicate`, Marcar como duplicado), los tres finales; las tres con los roles
  `SOCIAL_MANAGER`, `COMMUNITY_RELATIONS_OFFICER`, `STAKEHOLDER_MANAGER`, `COMMITMENT_MANAGER`, `GRIEVANCE_MANAGER` y
  `SOCIAL_RISK_MANAGER`. `accept` es de comando (`CommandTransitionGuard`); `reject` y `mark_duplicate` piden motivo
  (`TransitionReasonGuard`, ya en el código).

### Roles (`model/roles.json`)

- `ai_suggestion`: `["READ", "CREATE", "UPDATE"]` para SMG, CRO, SHM, CMM, GVM y SRM; nadie más.
- `ai_interaction`: `["READ", "CREATE"]` para SMG, CRO, SHM, CMM, GVM, SRM y `ANALYST`; nadie más.
- `restrictedFields`: `{"object": "ai_suggestion", "fields": ["evidence_quote"], "readers": [SMG, CRO, SHM, CMM, GVM, SRM,
  SIM, GAN]}`, los mismos lectores que la cita del candidato.

```python
# "GIN de texto completo sobre `to_tsvector('spanish', content)`" in the Índices bullet of a fixed table
FULL_TEXT = re.compile(r"GIN de texto completo sobre `to_tsvector\('(\w+)', (\w+)\)`")


def fixed_table(name):
    """A fixed table of the sgspe schema from its card (database-model.md §2.3 and §20): {"columns": [(name, type,
    required)], "primary_key": [...], "uniques": [[...]], "indexes": [[...]], "full_text": (configuration, column)}. Its
    Únicos bullet reads "clave primaria `id`; (`a`, `b`)" and its Índices bullet "(`a`, `b`); GIN de texto completo sobre
    `to_tsvector('spanish', content)`". Fails if the card is an object's or a bullet lost its shape."""
    lines = read("database-model.md").splitlines()
    card = cards().get(name)
    if card is None:
        raise ValueError(f"database-model.md has no card for {name}")
    start = next(i for i, line in enumerate(lines) if line == f"### `{name}`")
    end = next((k for k in range(start + 1, len(lines)) if lines[k].startswith("#")), len(lines))
    bullets = _bullets(lines, next(k for k in range(start, end) if lines[k].startswith("- **")))
    uniques, indexes = bullets.get("Únicos", ""), bullets.get("Índices", "")
    if not uniques.startswith("clave primaria") or not indexes:
        raise ValueError(f"card {name}: not a fixed table (no 'clave primaria' in Únicos or no Índices bullet)")
    primary, _, rest = uniques.partition(";")
    full_text = FULL_TEXT.search(indexes)
    return {
        "columns": [(f["name"], f["type"], f["required"]) for f in card.fields],
        "primary_key": ticks(primary),
        "uniques": _sets(rest),
        "indexes": _sets(FULL_TEXT.sub("", indexes)),
        "full_text": full_text.groups() if full_text else None,
    }
```

```python
def phase_roles(roles, model):
    """roles.json as it was for `model`: without the permissions and restricted fields of objects the model lacks."""
    names = {o["name"] for o in model["objects"]}

    for role in trimmed["roles"]:

    trimmed["restrictedFields"] = [e for e in trimmed["restrictedFields"] if e["object"] in names]
    return trimmed
```

```kotlin
// la clasificación de BC-18 (§4 de la especificación de F7, domain-model §4.7): la sugerencia y la interacción son raíces con
// `project` opcional, como export_log, evidence y early_warning_rule: sin proyecto son del tenant y no piden asignación; con
// proyecto, se acotan por él. desde F7, 35 raíces y 27 hijos
class ProjectScopeF7Test {
    private val project = UUID.randomUUID()
    private val catalog = ModelCatalog.fromClasspath()
    private val read: suspend (String, UUID) -> Map<String, Any?>? = { _, _ -> null }

    private fun resolve(
        objectName: String,
        before: Map<String, Any?>
    ) = runBlocking {
        val write =
            RecordWrite(
                UUID.randomUUID(),
                UUID.randomUUID(),
                UUID.randomUUID(),
                objectName,
                UUID.randomUUID(),
                RecordChangeKind.UPDATED,
                before,
                null,
                null,
                null
            )
        ProjectResolver.resolve(write, before, catalog::isRequiredRelation, read)
    }

    @Test
    fun `la sugerencia y la interaccion son raices con proyecto opcional`() {
        for (name in AI) {
            assertEquals(ReadGroup.ROOT, ProjectScope.readGroup(name), name)
            assertFalse(catalog.isRequiredRelation(name, ProjectScope.PROJECT), name)
        }
        assertEquals(35, ProjectScope.ROOTS.size)
        assertEquals(27, ProjectScope.CHILDREN.size)
    }

    @Test
    fun `sin proyecto no piden asignacion y con proyecto se acotan por el`() {
        for (name in AI) {
            val tenant = resolve(name, mapOf("project" to null))
            assertFalse(tenant.unresolved, name)
            assertTrue(tenant.projects.isEmpty(), name)
            assertEquals(setOf(project), resolve(name, mapOf("project" to project.toString())).projects, name)
        }
    }

    companion object {
        private val AI = listOf("ai_suggestion", "ai_interaction")
    }
}
```

```python
def sql_table(text, table):
    """{"columns": [(name, type, not_null)], "constraints": [...], "indexes": [...], "code": text} of `CREATE TABLE table
    (...)` and its `CREATE INDEX ... ON table ...` in a migration; "code" is the migration without its comments."""
    text = "\n".join(line.split("--")[0] for line in text.splitlines())
    body = re.search(rf"CREATE TABLE {re.escape(table)} \((.*?)\n\);", text, re.S).group(1)
    columns, constraints = [], []
    for line in (part.strip().rstrip(",") for part in body.split("\n")):
        if not line:
            continue
        if line.startswith("CONSTRAINT"):
            constraints.append(line)
        else:
            name, kind = line.split()[:2]
            columns.append((name, kind, "NOT NULL" in line))
    indexes = re.findall(rf"CREATE INDEX \w+ ON {re.escape(table)} (.*?);", text)
    return {"columns": columns, "constraints": constraints, "indexes": indexes, "code": text}

    compuesto y el GIN de texto completo en español, y sin claves foráneas entre esquemas (§2.3)."""

    @classmethod
    def setUpClass(cls):
        with open(KNOWLEDGE_SQL, encoding="utf-8") as f:
            cls.sql = sql_table(f.read(), "sgspe.knowledge_chunk")
        cls.card = design_docs.fixed_table("knowledge_chunk")

    def test_las_columnas_son_las_de_la_ficha_sin_embedding(self):
        wanted = [c for c in self.card["columns"] if c[0] != "embedding"]
        self.assertEqual(self.sql["columns"], wanted)
        self.assertNotIn("embedding", self.sql["code"])
        self.assertNotIn("vector", self.sql["code"].replace("tsvector", ""))

    def test_clave_unico_e_indices_de_la_ficha(self):
        constraints = " ".join(self.sql["constraints"])
        self.assertIn(f"PRIMARY KEY ({', '.join(self.card['primary_key'])})", constraints)
        for columns in self.card["uniques"]:
            self.assertIn(f"UNIQUE ({', '.join(columns)})", constraints)
```

```sql
CREATE TABLE sgspe.knowledge_chunk (
    id              uuid        NOT NULL DEFAULT gen_random_uuid(),
    organization_id uuid        NOT NULL,
    -- vacío si la evidencia es del tenant
    project_id      uuid,
    evidence_id     uuid        NOT NULL,
    -- la posición del fragmento en el documento

    content         text        NOT NULL,
    created_at      timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT knowledge_chunk_pk PRIMARY KEY (id),
    -- la reindexación de una evidencia reemplaza sus fragmentos por posición: idempotente
    CONSTRAINT knowledge_chunk_position_key UNIQUE (organization_id, evidence_id, chunk_index)
);

-- la recuperación filtra por tenant, proyecto y clasificación antes de ordenar por relevancia
CREATE INDEX knowledge_chunk_scope_idx ON sgspe.knowledge_chunk (organization_id, project_id, classification);
-- el texto completo en español: websearch_to_tsquery('spanish', :q) y ts_rank_cd sobre esta misma expresión
CREATE INDEX knowledge_chunk_content_fts_idx ON sgspe.knowledge_chunk USING gin (to_tsvector('spanish', content));
```

```kotlin
    // una ai_suggestion en proposed (WF-K) de `kind` del catálogo «Tipo de sugerencia de IA», con su interacción de AI-08 del
    // mismo proyecto; `target` es (objeto, id) del registro al que se refiere, si lo hay. la cita lleva un marcador sin id
    protected fun aiSuggestion(
        project: String?,
        kind: String = "CLASIFICACION",
        target: Pair<String, String>? = null,
        attributes: Map<String, Any?> = emptyMap()
    ): String =
        platformCreate(
            "ai_suggestion",
            mapOf(
                "project" to project,
                "suggestion_kind" to kind,
                "target_object" to target?.first,
                "target_record_id" to target?.second,
                "suggested_value" to "AMBIENTAL",
                "evidence_quote" to "[PERSONA] dijo que el agua del canal llega turbia",
                "confidence" to 0.82,
                "model" to AI_MODEL,
                "ai_interaction" to aiInteraction(project, "AI-08")
            ).filterValues { it != null } + attributes
        )

    // un commitment_candidate de la IA en proposed, como lo guardará SuggestionWriter (plan 7.2b): ai_generated, confianza,
    // cita seudonimizada, su interacción y, si se dan, la evidencia y la interacción de origen; suggested_owner_user_email
    // vacío (el responsable lo elige quien acepta)
    protected fun aiCandidate(
        project: String,
        sourceEvidence: String? = null,
        engagement: String? = null,
        interaction: String = aiInteraction(project)
    ): String =
        platformCreate(
            "commitment_candidate",
            mapOf(
                "project" to project,
                "proposed_text" to "Reparar el canal de riego de la Comunidad Ejemplo antes de la siembra",
                "evidence_quote" to "[PERSONA:00000000-0000-0000-0000-000000000001] pidió reparar el canal",
                "beneficiaries_text" to "[PERSONA] y las familias del sector",
                "confidence" to 0.74,
                "ai_generated" to true,
                "ai_interaction" to interaction,
                "source_evidence" to sourceEvidence,
                "engagement" to engagement
            ).filterValues { it != null }
        )

    // un cambio y una baja como la plataforma, con la marca SgspeWrite: así escribirán los comandos de sgspe.ai
    protected fun platformUpdate(
        objectName: String,
        id: String,
        attributes: Map<String, Any?>
    ): RecordResponse =
        runBlocking {
            platformService.asPlatform(organizationId()) {
                platformRecords.update(objectName, UUID.fromString(id), attributes, "cambio de prueba como la plataforma")
            }
        }

    protected fun platformDelete(
        objectName: String,
        id: String
    ) {
        runBlocking {
            platformService.asPlatform(organizationId()) { platformRecords.delete(objectName, UUID.fromString(id), "baja de prueba como la plataforma") }
        }
    }

    companion object {
        const val AI_MODEL = "modelo-de-prueba"
    }
}
```

```kotlin
package sgspe.workflow

import org.junit.jupiter.api.Assertions.assertEquals
import org.junit.jupiter.api.Assertions.assertTrue
import org.junit.jupiter.api.Test
import org.springframework.http.HttpStatus
import sgspe.F7ApiTest

// WF-K de las sugerencias de IA (workflows.md, «WF-K para sugerencias de IA»; RQ-AI-001, RQ-AI-003, RQ-AI-015): una
// sugerencia es apiOnly, nace en `proposed` y la decide una persona. aceptar es de comando (CommandTransitionGuard): por la
// API genérica, 403; rechazar y marcar duplicado piden motivo (TransitionReasonGuard) y no cambian el registro destino. la
// aceptación por POST /api/sgspe/ai-suggestions/{id}/accept y la cuenta de servicio las suma el plan 7.2b
class AiSuggestionWorkflowApiTest : F7ApiTest() {
    private val social by lazy { member("SOCIAL_MANAGER") }
    private val risks by lazy { member("SOCIAL_RISK_MANAGER") }

    @Test
    fun `una sugerencia nace propuesta y la API generica no la da de alta, ni al admin`() {
        val id = aiSuggestion(testProject())
        assertEquals("proposed", state("ai_suggestion", id))
        val attributes = sample("ai_suggestion") + ("project" to testProject())
        for (caller in listOf(social.token, token)) {
            assertEquals(HttpStatus.FORBIDDEN, exchange("POST", "/api/objects/ai_suggestion/records", mapOf("attributes" to attributes), caller).status)
        }
    }

    // Review Focus 1 del plan 7.1
    @Test
    fun `aceptar por la API generica es 403 COMMAND_ONLY y la sugerencia sigue propuesta`() {
        val id = aiSuggestion(testProject())
        val refused = transition("ai_suggestion", id, "accept", social.token, "la acepto")
        assertEquals(HttpStatus.FORBIDDEN, refused.status, refused.body)
        assertEquals("COMMAND_ONLY", code(refused))
        assertEquals("proposed", state("ai_suggestion", id))
    }

    @Test
    fun `rechazar pide motivo y despues ya no se decide`() {
        val id = aiSuggestion(testProject())
        val without = transition("ai_suggestion", id, "reject", social.token)
        assertEquals(HttpStatus.BAD_REQUEST, without.status, without.body)
        assertEquals("REASON_REQUIRED", code(without))
        move("ai_suggestion", id, "reject", social.token, "la categoría no corresponde")
        assertEquals("rejected", state("ai_suggestion", id))
        assertEquals(HttpStatus.CONFLICT, transition("ai_suggestion", id, "reject", risks.token, "otra vez").status)
        assertTrue(available("ai_suggestion", id, risks.token).isEmpty(), "una sugerencia rechazada no ofrece transiciones")
    }

    // RQ-AI-015 (ASM-053): marcar duplicado es una decisión humana con motivo y nunca fusiona ni toca el registro destino
    @Test
    fun `marcar duplicado pide motivo y no cambia el registro destino`() {
        val engagement = engagement(testProject())
        val before = record("engagement", engagement)["attributes"]
        val id = aiSuggestion(testProject(), "BORRADOR DE ACTA", target = "engagement" to engagement)
        assertEquals(HttpStatus.BAD_REQUEST, transition("ai_suggestion", id, "mark_duplicate", risks.token).status)
        move("ai_suggestion", id, "mark_duplicate", risks.token, "repite el borrador de acta de otra sugerencia")
        assertEquals("duplicate", state("ai_suggestion", id))
        assertEquals(before, record("engagement", engagement)["attributes"])
    }

    @Test
    fun `quien solo lee no decide y el listado lo explica`() {
        val id = aiSuggestion(testProject())
        // AUDITOR lee todo el tenant sin UPDATE (security.md §7.1)
        val auditor = userWithRole("AUDITOR")
        assertEquals(HttpStatus.FORBIDDEN, transition("ai_suggestion", id, "reject", auditor.token, "x").status)
        val offered = available("ai_suggestion", id, auditor.token)
        assertEquals(setOf("accept", "reject", "mark_duplicate"), offered.keys)
        assertTrue(offered.values.all { it == (false to "requires permission UPDATE") }, "$offered")
        assertEquals("proposed", state("ai_suggestion", id))
    }
}
```
